# 04_UI仕様書

## Dungeon Game Ver.1.0（文書Ver.1.90）

## 要点

- タイトルは3モードを一画面に表示。プレイ画面は3D迷宮、ステージ・鍵状態・状況、探索マップ、操作の4領域。
- 探索マップは到達済みの情報だけを表示し、現在地を青いドラゴンで示す。HPは探索中も表示する。
- 戦闘はダンジョン領域に敵を表示し、HP・メッセージ・Playerリアクションを状況欄に置く。攻撃・逃走ボタンはギブアップの横。
- 鍵・剣の取得演出中は移動を止め、敵セリフとBGMの切り替えは現行メモに従う。
- 画面サイズ別の寸法や演出の細部は、以下の各項目を参照する。

## 現行UIの挙動メモ（2026-10-21）

- 敵との遭遇セリフは5秒、撃破セリフは3秒表示し、新しい遭遇セリフが始まる時点で前の撃破セリフを閉じる。
- 逃走後も敵の残りHPを敵マスごとに保持し、同じ敵と再戦すると前回の残りHPから開始する。
- 鍵または剣を取得したイベントの発生時点でゲーム側の移動ロックを有効にし、演出を閉じるフェードの完了後に解除する。画面全体のフリックとコマンド領域のフリックを止め、壁衝突後の入力停止中もコマンド領域から移動できない。
- 戦闘BGMを再生できない場合は探索BGMを続ける。BGMの正式なファイル割り当てはゲーム仕様書の「音源の正式な割り当て」を参照する。音源名と拡張子のコード上の対応は `AudioPlayback.swift` の `AudioResource` に集約する。
- ゲームオーバーでは約1.85秒の低音インパクトと下降音を一度再生し、視差効果を減らす設定に応じてプレイヤーの倒れる演出を省略する。

## 1. UIの目的

本UIは、ファミコン時代のWizardryや女神転生を想起させる、シンプルで情報が明確な画面を基本とする。

プレイ画面は、以下の4領域で構成する。

1.  上部：ダンジョン画面（3Dダンジョン表示）
2.  ステージ名・鍵状態・メッセージ表示
3.  探索マップ（オートマップ）表示
4.  下部：コマンド・操作表示

本UIには、面を選ぶスタート画面と、プレイ画面がある。上記および以下の領域の構成は、プレイ画面のものである。スタート画面は§13、クリア表示は§14、ステージ・鍵状態・メッセージ表示は§16で定める。

## 3. ① ダンジョン画面（3Dダンジョン表示）

### 3.1 役割

プレイヤー視点から見た現在のダンジョン構造を表示する。

### 3.2 基本デザイン

-   壁：暗い灰色・茶色を基調にした石積みブロック表現
-   ブロック間に暗い目地と控えめな明暗差を付け、奥行きに応じて暗くする
-   床・天井も壁より暗い石材で表現し、通路の形状が読み取れるようにする
-   マップ構造から壁面を生成し、固定画像の貼り付けに依存しない
-   過度な装飾を避け、壁・床・天井の境界を見分けやすくする
-   画面中央をプレイヤーの視線方向の基準とする
-   遠近感を持たせる

### 3.3 描画原則

3D表示は「何マス先まで表示する」という固定方式ではなく、マップ構造から必要な壁・通路・床・天井を求め、透視投影して表示する。

同じ投影ルールをすべての構造に適用する。

対象： - 直進 - 左折 - 右折 - T字路 - 十字路 - 突き当たり - 部屋

### 3.4 重要な完成基準

突き当たりの壁は、左右の壁や床・天井との接続位置を正しく計算する。

特に、 - 横長・縦長の不自然な長方形にならない - 壁同士がずれない -
奥の壁が正しい透視投影になる - 左右対称になるべき構造は左右対称になる -
石材の目地が壁面の端から不自然にはみ出さない

ことを完成基準とする。

### 3.5 表示禁止

-   マップ上存在しない壁を表示しない
-   未確認の構造をオートマップへ先行表示しない
-   固定4セル表示だけを前提にした特殊処理を採用しない
-   パターンごとに別々の座標を手作業で大量に指定しない

### 3.6 表示領域の形

3D表示領域は正方形とする。突き当たりの壁は、この領域内で正方形として投影される。

## 4. ③ 探索マップ（オートマップ）

### 4.1 役割

プレイヤーが実際に探索して確認した範囲を記録する。

### 4.2 表示内容

-   探索済みセル
-   確認済みの壁
-   確認済みの通路
-   プレイヤー位置
-   プレイヤーの向き
-   必要に応じて既に確認した特殊地点

### 4.3 非表示内容

まだ到達していない場所は原則として表示しない。

特に、 - T - K - G - 未到達の通路 - 未確認の壁

を事前に表示しない。

### 4.4 プレイヤー表示

現在位置を明確に表示する。

現在位置は青いドラゴンをかたどったドット絵カーソルで示す。ドラゴンはマスの内側に収め、向きはダンジョン画面で確認する。

表示例：

``` text
  ●
```


### 4.5 マップ更新

プレイヤーが新しいセルへ移動した時点で、そのセルを探索済みとする。

その時点で確認できる壁・通路情報を記録する。

### 4.6 オートマップの表示ルール

- 探索済みの床を緑系で塗り、到達のたびにマスを色づけする。
- 探索済みのマスの四辺のうち、隣が壁である辺を、石材色の線で表示する。
- 探索済みでないマスには、何も描かない。
- T・K・G は、そのマスへ到達した後にのみ記号を表示する。
- プレイヤーの現在位置は青いドラゴンのドット絵カーソルで示す。向きはダンジョン画面で確認する。
- 面全体の大きさが領域に収まるよう、領域に合わせて拡大縮小して表示する。
- T・K・G の到達済みマスは、床色と記号に控えめな識別色を使う。未探索マスは色も記号も表示しない。
- 青いドラゴン型カーソルは探索済み床や特殊マスと区別できる色で表示し、現在位置を隠さない大きさでマス中央に収める。

## 5. ④ コマンド・操作表示

### 5.1 役割

プレイヤーが現在使用できる操作を分かりやすく提示する。

操作は次の5つとする。

-   左を向く
-   前進
-   右を向く
-   反対方向を向く（180度反転）
-   ギブアップ

マスを移動するのは前進だけとする。左右フリックはその場で90度旋回し、下フリックはその場で180度反転する。方向転換では位置を変えない。

### 5.2 操作方法

移動はフリック入力で行う。ダンジョン画面、ステージ・鍵表示、状況メッセージ、探索マップ、下部のフリック案内領域から操作できる。

ただし、操作方法を変更してもゲーム仕様そのものは変更しない。

### 5.3 操作表示

フリック方向と動作が画面内の案内で分かるようにする。

-   上フリックで前進、下フリックでその場で180度反転、左・右フリックでその場で旋回する。
-   フリック方向に合わせて案内の矢印を回転させる。
-   3Dダンジョン画面、表示ステータス、状況メッセージ、探索マップ、下部のフリック案内領域を操作可能にする。
-   探索マップの表示領域を広げ、指でフリックを始めやすくする。
-   ギブアップはフリック可能領域から分け、右寄せに配置する。高さは、指で押しやすい44以上とする。ステージ選択・確認・クリア画面などのボタンにも押下反応を付ける。
-   ギブアップを押すと、確認表示を出す（§15）。

``` text
↑ 上フリック：前進　↓ 下フリック：反対方向を向く
← 左フリック：左を向く　右フリック：右を向く →

[ギブアップ]
```

## 6. 文字・線・色

### 6.1 基本方針

レトロゲーム風の視認性を維持しつつ、現在の端末でも読みやすいUIとする。

### 6.2 色

基本配色： - 背景：黒系 - 石材：暗い灰色・茶色 - 探索済みの床：緑系 - 基本文字：白系

鍵は金色、トラップは赤系、ゴールは明るい中間色を使ってよい。色数を絞り、探索済み／未探索と重要地点をひと目で区別できるようにする。

### 6.3 線

石積みの目地と壁の輪郭は、奥行きに応じて見やすい太さにする。

ただし、遠近感を表現するために必要な場合は、仕様として定めた範囲で調整する。

## 7. 画面サイズへの対応

端末の画面サイズが変わっても、 - 3D表示が切れない - マップが切れない -
コマンドが操作可能 - 重要情報が重ならない

ことを優先する。

固定ピクセル値だけに依存せず、可能な範囲で親ビューのサイズからレイアウトを決定する。

## 8. UIとゲームロジックの分離

UIはゲームロジックと分離する。

UI側： - 表示 - ボタン - 操作入力

ゲーム側： - プレイヤー位置 - 向き - マップ - 探索状態 - T/K/G -
クリア状態

UIから直接マップデータを書き換えるなど、責務を混在させない。

画面状態（スタート画面・プレイ画面・クリア表示・ゲームオーバー表示）、選択中の面、ギブアップの実行も、ゲーム側で管理する。UI側は、ボタンの入力をゲーム側へ伝え、状態に応じて画面を切り替えて表示するのみとする。

## 9. 3Dパターンの確認順

完成画面を以下の順番で確認する。

1.  直進
2.  左折
3.  右折
4.  T字路
5.  十字路
6.  突き当たり
7.  部屋

各パターンは単独で正常であることを確認した後、組み合わせた状態でも確認する。

## 10. 完成画面の基準

画面イメージは画面構成とレイアウトの参考とする。2026-10-02に確定した画像は旧配色・旧素材の記録であり、石積み・色分けなどの見た目は本書の§3、§4、§6の定義を優先する。画像は`docs/`に3枚保存してある。

- 「プレイ」：プレイ画面
- 「スタート」：スタート画面
- 「ゴール」：クリア表示

コード側で「それらしく見える」ことだけを完成条件にしない。

完成画面との比較で、 - レイアウト - 3D表示 - マップ - コマンド - 線 -
文字 - 余白 - 全体バランス

を確認する。

### 10.1 基準となる主な寸法

画面の幅390、高さ844を想定した値。画面サイズが変わるときは、親ビューの大きさから決める（§7）。

| 項目 | 基準 |
|---|---|
| 左右の余白 | 16 |
| 3Dダンジョン表示 | 幅いっぱいの正方形、角丸12、石材になじむ控えめな枠 |
| ステージ・鍵状態 | 3D表示の下に常時表示。ステージ名と「鍵：未取得／所持／不要」を示す |
| メッセージ表示 | 通常は最大2行。長い状況文は意味のまとまりで改行して最大3行まで表示し、行間を確保する |
| オートマップ | 3D表示と同じ幅、高さ210を基準に画面に合わせて調整、角丸12、石材色の細い枠 |
| フリック操作領域 | 3D画面・ステータス・メッセージ・探索マップ・下部案内領域。上で前進、下で180度反転、左右でその場旋回 |
| ギブアップ | 幅120、高さ44、右寄せ |

## 11. UI変更ルール

UIを変更する場合も、ゲーム仕様を勝手に変更しない。

UI変更によってゲームロジックへの影響が発生する場合は、変更内容と影響範囲をチームへ共有する。

## 12. 完成条件

以下をすべて満たした状態をUI完成とする。

-   4領域のレイアウト（3D表示、メッセージ、オートマップ、コマンド・操作）が正常
-   3Dダンジョンが正しく表示される
-   石積み風の壁・床・天井が通路の奥行きを保って表示される
-   オートマップが探索情報だけを表示する
-   到達したマスが色づき、未探索情報を表示しない
-   ステージ名と鍵状態が常時確認できる
-   ダンジョン画面・探索マップ・下部案内領域でフリック操作ができる
-   上フリックだけで1マス前進し、左右フリックでその場旋回、下フリックでその場180度反転する
-   案内の矢印がフリック方向に合わせて操作中に回転する
-   通常の状況メッセージは最大2行、複数の案内を含む長文は意味のまとまりで改行して最大3行まで表示される
-   現在位置と方向が分かる
-   前進と方向転換（左・右旋回、180度反転）およびギブアップが操作できる
-   スタート画面から面を選んで開始できる
-   クリア表示のあと、スタート画面に戻れる
-   ギブアップの確認表示が正しく動作する
-   チュートリアルの案内が操作に応じて進み、鍵取得後にゴールへ案内する
-   壁に当たったとき、状況と次に取れる操作が分かる
-   画面サイズ変更で重大な崩れがない
-   Kで鍵を初めて取得したときに、宝箱と鍵の演出が表示され、再度Kに入っても繰り返されない
-   チュートリアルで、操作に応じた案内が順に表示され、鍵取得後にゴールへ案内する
-   案内文では上部を「ダンジョン画面」、下部の地図を「探索マップ」と呼ぶ
-   壁や鍵のかかったゴールで、状況が分かるメッセージを表示する
-   3Dの各パターンを確認済み
-   実機で確認済み
-   完成画面イメージと比較済み
-   既存ゲーム機能に悪影響がない

## 13. スタート画面

### 13.1 役割

ゲーム起動時に最初に表示する画面。プレイヤーがチュートリアル、試練の迷宮、ランダムステージから選んで開始する。

### 13.2 構成

-   石造りの門と金色の装飾を使った、クラシックな迷宮RPG風の意匠とする
-   タイトルは「What's gathered?」と「Run!」を改行して表示し、日本語名「ワギャラン」も表示する
-   日本語名「ワギャラン」の左右に青いPlayerドラゴンと紫のドラゴンを配置し、紹介文の下にスライム・スケルトン・ガーゴイルを並べる。5体すべてに呼吸・上下動の待機アニメーションを繰り返す。
-   門・タイトル文字・キャラクターのサイズは、端末の表示高に応じて調整する。通常の画面では門幅64・高さ56を基準に、非常に低い画面では幅50・高さ44へ縮小する。タイトルとボタンの文字は読みやすい通常サイズを優先する。
-   タイトル下に「ファミコン時代の Wizardry・女神転生を思わせる、」「グリッド型の3Dダンジョン探索ゲーム」の2行を表示する。
-   続けて「鍵を見つけてゴールを目指そう」「最短クリアを目指しタイムを競おう！」の2行で目的を案内する。
-   紹介文と目的は暗い半透明の枠にまとめ、文字の階層と余白で区別する。
-   「探索モードを選ぶ」見出しの下に、同じ幅・高さ・様式の選択カードを縦に並べる。各カードにはモードを表すアイコン、名前、短い説明を表示する。
    - 「チュートリアル」：操作と鍵の取り方を練習
    - 「試練の迷宮」：固定マップを探索
    - 「ランダムステージ」：通路とイベントが毎回変わる
-   ランダムステージを一度開始した後は、「前回の迷宮を再現」も選択できる。前回と同じseedを使い、seed値も説明に表示する。
-   操作説明は選択カードの下に2行で表示し、狭い画面でも読みやすい文字サイズを保つ。
-   背景は黒・暗い石色を基調に、文字と装飾には白・古い金色を使う。全カードの様式と押下反応を統一する。
-   タイトル画面ではスクロールを使わず、モード選択から操作説明まで1画面に収める。文字とボタンを小さくしすぎず、門やキャラクター周辺の余白を調整する。

### 13.3 遷移

-   面のボタンを押すと、その面のプレイ画面に移る。
-   クリア表示・ギブアップのあと、この画面に戻る。

## 14. クリア表示

-   G でクリア条件を満たしたとき、クリア表示を出す。
-   画面全体を、細い白の枠で囲み、中央に、大きな文字で「おめでとう!」、その下に「ゲームクリア」を表示する。
-   表示中に、スタート画面へ戻る操作（ボタン「スタート画面へ」）を用意する。押すと、スタート画面に戻る。
-   ボタンを押している間は、コマンドボタンと同じ視覚反応を表示する。
-   チュートリアルをクリアしても自動では進まず、「次の迷宮へ」を押すと試練の迷宮を開始する。
-   一定時間で、自動でスタート画面に戻す方式は、将来の検討事項とする（Ver.1.2では採用しない）。
-   試練の迷宮・ランダムステージでは「もう一度遊ぶ」ボタンを表示し、同じ面を最初から開始する。ランダムステージは同じseedを使う。
-   「次の迷宮へ」はチュートリアルの次に試練、試練の次にランダムへ進める。ランダムステージでは「新しいランダムステージへ」と表示し、新しいseedで開始する。
-   「もう一度遊ぶ」と「スタート画面へ」は次の迷宮へ進むボタンと併せて残す。
-   試練の迷宮・ランダムステージは初回プレイから計時・記録し、クリア画面に「今回のタイム」と「最短クリアタイム」を表示する。
-   最短タイムとTOP100は試練の迷宮・ランダムステージごとに端末内へ保存する。ランダム面の再挑戦は同じseedを使い、記録はseedをまたいでランダムステージ全体で比較する。
-   チュートリアルには再挑戦ボタンとタイム表示を追加せず、「試練の迷宮へ」と「スタート画面へ」を表示する。
-   チュートリアルのクリア画面には「次からはクリアタイムが記録されます」と表示し、進行ボタンを画面下部に寄せる。
-   クリア画面の縦スクロール領域は内枠の内側に収め、見出し・文字・ボタンが枠線に重ならないようにする。ランキングは専用の枠内でスクロールする。
-   クリア画面の主要な説明・タイム・ボタン文字は読みやすいサイズに統一し、狭い画面では画面内スクロールで全項目へ到達できるようにする。
-   名前入力欄を選択すると、キーボードの入力確定キーとキーボード上の「完了」ボタンのどちらでも閉じられる。
-   入力欄の横に「記録」ボタンを常時表示し、入力中に押すと記録後にキーボードを閉じる。名前入力中に画面をスクロールしてもキーボードを閉じられる。
-   Debugビルドでもランキング欄には保存済みの実記録だけを表示する。サンプルデータや切り替えボタンは表示しない。`-debug-clear-screen` によるクリア画面の直接表示は維持する。
-   「記録」を押したらボタンを「登録中」に変え、登録処理中の案内を表示する。処理後はTOP100内の順位、または圏外であることを知らせる。登録された行まで一覧をスクロールし、金色で強調する。
-   有効な名前を入力して「記録」を押したとき、登録処理の受付時に既存の短いUI効果音を再生する。
-   ランキングはクリアタイムの実値が短い順、同じ実値なら登録日時が早い順に並べる。順位は一覧上の位置とし、表示が同じ0.1秒でも実値が異なる場合は短い記録が上位になる。
-   TOP100に登録済みの名前は入力欄から編集できる。元の名前と異なる文字を入力すると「更新」ボタンが有効になり、押すと同じランキング行の名前だけを変更する。クリアタイム・登録日時・順位は維持する。登録に入らなかった記録は編集できない。
-   視差効果を減らす設定では、登録中・登録結果の案内は維持し、待ち時間と移動アニメーションを省く。

## 15. ギブアップの確認表示

-   ギブアップを押すと、「ギブアップしますか？」の確認と、「はい」「いいえ」の2つのボタンを表示する。
-   「はい」：現在のプレイを終了し、スタート画面に戻る。
-   「いいえ」：確認を閉じ、プレイ画面に戻る。プレイの状態は変わらない。
-   確認の表示中は、他の操作を受け付けない。
-   「はい」「いいえ」のボタンにも、コマンドボタンと同じ押下反応を表示する。

## 16. ② ステージ・鍵状態・メッセージ表示

### 16.1 役割

現在のステージ名と鍵の状態を常時示し、プレイ中の出来事（鍵の取得、トラップ、壁、扉が閉まっている、など）とチュートリアルの操作案内を伝える。

### 16.2 表示

-   3Dダンジョン表示の直下に、ステージ名と鍵状態を1行で表示する。鍵状態は「未取得」「所持」「不要」のいずれかとする。
-   3Dダンジョン表示にはキャラクター画像を重ねない。
-   その下、探索マップの直上に、高さ80のイベントメッセージまたは段階案内を表示し、右隣に約78×74のPlayer画像を表示する。
-   文字は白系を基本とし、鍵を所持している場合は金色で目立たせる。
-   通常は最大2行、高さ70、文字16、行間2を基準にする。複数の案内を含む長文は意味のまとまりで改行し、最大3行まで表示する。表示する内容がないときは「迷宮を探索しよう」と表示し、領域の高さを維持する。
-   状況メッセージ横のPlayerは待機中に呼吸し、プレイヤーの位置または向きが変わったときにジャンプアニメーションを再生する。
-   メッセージの内容は、ゲーム仕様書（§13.6）で定める。

### 16.3 ステップアップ式チュートリアル

-   チュートリアル面では、操作や出来事に応じて次の案内を順に表示する。
    1. 「上フリックで1マス進もう！」
    2. 「左右フリックで向きを変えよう！」
    3. 「上のダンジョン画面で進む方向を見て、下の探索マップで現在地を確認しよう！」
    4. 「探索マップを2本指で広げて拡大しよう！」
    5. 「宝箱を探して鍵を見つけよう！」
    6. 鍵取得後に「鍵を手に入れた！ゴールを探そう！」
-   移動先が壁の場合は段階を進めず、状況に応じた壁メッセージを表示する。
-   イベントの状況メッセージは段階案内より優先し、イベント後は現在の段階案内に戻す。
-   案内では上の表示領域を「ダンジョン画面」、下の地図を「探索マップ」と呼ぶ。
-   チュートリアルの探索マップをピンチ操作で拡大したら次の段階へ進む。ピンチ中と直後に移動フリックを処理しない。
-   イベントの状況メッセージは段階案内より優先し、イベント後は現在の段階案内に戻す。
-   試練の迷宮・ランダムステージでは段階式の操作案内を表示しない。

## 17. K取得時の宝箱・鍵の演出

- プレイヤーがKに初めて入ったとき、向きによらず3Dダンジョン表示領域の中央に閉じた宝箱を表示する。メッセージ「鍵を手に入れた」が表示されてから1秒後に鍵取得演出を始める。
- 取得演出中は閉じた宝箱から開いた宝箱へ切り替え、鍵を浮かべる。演出後、プレイヤーがKマスにいる間は宝箱画像を表示しない。向きを変えても画像や取得演出・効果音は表示・再生し直さない。

- 戦闘または壁衝突でHPが0になったとき、状況欄に「力尽きた……」を約1.2秒表示した後、プレイ画面全体を覆うゲームオーバー画面を表示する。
- 画面には「力尽きた……」「GAME OVER」「HPが0になった」を表示し、クリア画面と同じMaruMonicaの書体を使う。画面が現れたときに `Map/Audio/ゲームオーバー.wav` を一度再生し、青いプレイヤーが短く倒れる演出を加える。
- しりとりでプレイヤーの敗北が確定した場合も同じデザインのゲームオーバー画面を表示する。この場合は「HPが0になった」を「時間切れ・・・」に、補足文を「しりとりはここで終了です」にする。
- ゲームオーバー画面には「スタート画面へ」ボタンを置き、押すまでは結果画面を表示し続ける。
- ゲームオーバー画面の内容は短くフェードインし、少し上から収まる演出にする。プレイヤー画像も短く傾けて倒す。視差効果を減らす設定では移動・フェード・倒れる動きを行わず、静止状態で表示する。
- ゲームオーバー後はBGMとタイマーを停止し、クリアタイムやランキングを記録しない。
